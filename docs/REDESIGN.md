# Redesign on the mandatiq design system

Status: proposed for this fork, revision 2, drafted 11 September 2026, revised 22 September 2026. Produced from an eight-subsystem map of the code with file:line evidence, three independently written designs (minimal-churn, fidelity-first, product rethink) and three gap studies (screenshots and visual regression, performance budget, installed-PWA behaviour), then put through three rounds of adversarial review (eight lenses per round; each finding refuted or confirmed with its own evidence), which corrected 193 claims. Every technical claim the design rests on was verified by compiling CSS against the installed `tailwindcss` 4.3.0 and `daisyui` 5.5.20, and every line number quoted below was re-checked with grep. Line numbers are true as of commit `a8da281`; re-grep before relying on one.

This document plans the next iteration: a visual redesign of Libre Closet that follows the mandatiq brand guidelines v2.0 (`/home/joao/Documents/mandatiq-brand-v2`, guide PDF and `tokens/tokens.json`). It covers colour, typography, components, the shell, identity, copy, accessibility, the quality gates that keep the result compliant, and the order of delivery.

Decisions already taken by the owner on 11 September 2026, restated so nobody reopens them:

1. **Design system only, neutral identity.** The mandatiq palette, type, dark-mode tokens, accessibility rules and tone apply to the whole UI. The app keeps its own neutral "Libre Closet" identity with a new simple mark. No mandatiq logo, wordmark or monogram appears anywhere in the app, manifest, icons or email. "This fork is maintained by mandatiq" (always lowercase) appears only at the end of `README.md` and on the About page. No mandatiq logo file enters the repo, so `TRADEMARK.md` is not required (guide ch. 11 ties it to logo files).
2. **The Lazztech marks leave the app.** Logo, icon, wordmark, JSON-LD Organization, watermark source, push icon, `llms*.txt`, `robots.txt` and the footer credit are replaced by the new mark and the fork's own URLs. Lazztech LLC stays credited as the original builder in `README.md` and on About (guide ch. 10: say "built by" only about the people who built it).
3. **`tokens/mandatiq-tokens.css` is not imported.** Its `--mq-surface` alias is a self-reference (`--mq-surface: var(--mq-surface)`, lines 14 and 32), which CSS treats as a cycle, so the property is invalid in light mode. Values are taken from `tokens.json` by hex; the defect is reported to the brand repo separately (Appendix B).
4. **Deployment context.** Personal self-hosting, most likely one user with `AUTH_ENABLED=false`, installed as a PWA over HTTPS. No `upstream` git remote is configured and the fork is 160+ commits along its own history, so upstream-merge friction is a soft cost, not a constraint.
5. **Conventions.** PRs of roughly 100–400 lines where the work allows; this file is the design record; all six locales stay key-complete; `public/bundle.css`, `public/sw.js`, `public/js/share-stash.js` and `views/assets/src-sw.js` are build outputs and never committed.

## 1. Summary

- **Colour lands in CSS, not templates.** Every template colour already flows through daisyUI's `--color-*` roles, so the brand is installed as two `@plugin "daisyui/theme"` blocks (light default, dark under `prefers-color-scheme`) whose values are the `tokens.json` hexes, with the page background set through daisyUI's own `--root-bg` variable so the page is Paper while cards stay White. This was compiled and checked, not assumed (section 5.1).
- **One override block fixes the component defaults that break the guide** (12 px labels, 40 px buttons, base-content focus rings, 20 %-alpha input borders, filled status alerts, bevel shadows). It is written as `@layer utilities { :where(...) {} }`, which beats daisyUI's nested sub-layers at zero specificity and, apart from the five focus rules, loses to any utility class a template applies.
- **Fonts are self-hosted variable WOFF2** (Inter, Plus Jakarta Sans, JetBrains Mono from pinned `@fontsource-variable` packages), committed under `public/assets/fonts/`, preloaded, precached and served immutable. Body 16 px, headings 32/24/19 px in Plus Jakarta Sans with −0.02 em tracking.
- **The shell is rebuilt**: a sticky 56 px header (mark, name, section links at `lg+`, account control only when auth is on) replaces the fixed 64/69 px navbar and the drawer that is empty for a self-hoster; the bottom dock stays on phones and hides at `lg+`; every page gets one container class so no template hardcodes header or dock offsets any more; a skip link and landmarks are added.
- **Components are made compliant one by one**: 44 px buttons, labelled fields with icon-plus-text validation, alerts as Ink text with the status colour on the icon and a 4 px rail, neutral filter pills and badges, keyboard-operable filter chips, calendar chips identified by name and thumbnails instead of hue, a CSS spinner that respects reduced motion, a `{{icon}}` helper with `aria-hidden` by construction.
- **Identity**: a single-stroke hanger mark in `currentColor`, exported to favicon, apple-touch, 192/512 any and maskable icons, a 1200×630 Open Graph image and the watermark; the landing page advertises this fork's repository and image; About, privacy and terms are rewritten for a self-hosted instance.
- **Copy**: sentence case, words instead of symbols, British spelling in the English UI, specific error messages, locale-aware dates, every user-facing hard-coded English string moved into the six locale files (the `/chat` demo strings and push-test payload excepted, section 2).
- **Gates make it stick**: a brand allowlist test that checks the theme against `tokens.json` approved pairings and forbids off-palette classes, an axe Playwright spec over the app routes, Lighthouse with `font-size` and `color-contrast` back at error and explicit CLS/byte ceilings, a bundle-size test, manifest/icon assertions, two Chromium-only visual-regression projects (desktop and mobile), and a script that regenerates the marketing screenshots from seeded test data.
- **Delivered as 18 PRs**; four of them exceed 400 lines: the theme with its brand spec, the primitives PR (which carries the one-time regeneration of the stale `i18n.generated.ts`, 5.6), the copy pass and the privacy/terms rewrite, the last two because six locale files must change together.

## 2. Goals and non-goals

Goals

- Every foreground/background pairing the UI produces at rest is in `tokens.json` `approved_pairings`, in light and dark; daisyUI's `.btn` hover and active states mix the resting button colour with 7 % / 5 % black (a recorded deviation, section 8: White on Cobalt rises to 8.4:1, Ink on darkened Surface falls to 12.3:1 and Ink on darkened Periwinkle to 6.1:1, all above 4.5:1).
- Every rule in guide chapters 06–10 and 14 that can be expressed in code is enforced by a test, not by review.
- The app is recognisably its own product (neutral mark, own name) while looking like it belongs to the mandatiq design system.
- WCAG 2.2 AA on the pages a self-hoster uses: focus rings, 44 px targets on touch, 16 px body, no colour-alone meaning, reduced motion respected, works at 320 px and 200 % zoom.
- Keep every DOM contract that JavaScript, hyperscript and the Playwright suite depend on (section 3), so the existing tests keep passing throughout.
- Keep the zero-config Docker promise: no new required environment variable.

Non-goals for this iteration

- A user-facing theme toggle; dark mode stays OS-driven, exactly as the brand tokens do.
- Renaming the product, the manifest `id`/`start_url`/`scope`, or any route.
- Hardening CSP (nonces, dropping `'unsafe-inline'`); inline handlers and hyperscript stay.
- Replacing or patching `@khmyznikov/pwa-install`, `pulltorefreshjs` or SortableJS beyond options and CSS.
- Translating Nest exception messages, the `(cloned)` suffix, import note labels, or the password-reset email body (it is compiled outside the view engine and has no locale).
- The `/chat` demo strings emitted over SSE by `src/app.controller.ts:85-127` ("User", "Assistant", "Hello World") and the push-test payload sent from that page's button (`notification.controller.ts:48-49`, `title: 'Test Web Push', body: 'body'`) stay English.
- Visible garment colour swatches, a categorical palette for content, or a Portuguese locale.
- The `@tailwindcss/typography` plugin; long-form pages are styled from the base scale.
- Removing the photo watermark or the `/chat` page.

## 5. Design

### 5.1 Theming

**Mechanics, verified by compiling** with the repo's `@tailwindcss/cli` 4.3.0 and `daisyui` 5.5.20 on 11 September 2026:

1. `@plugin "daisyui" { themes: false }` stops the stock palettes from being emitted at all.
2. Two `@plugin "daisyui/theme" { … }` blocks named `light` (`default: true`) and `dark` (`prefersdark: true`) compile to `:where(:root), :root:has(input.theme-controller[value=light]:checked), [data-theme="light"] { … }` and `@media (prefers-color-scheme: dark) { :root:not([data-theme]) { … } }`, both in `@layer base` after daisyUI's `rootcolor` rule. Every custom declaration inside a block (including `--root-bg` and `--mq-*`) is spread into the selector.
3. Because the themes are named after the built-ins, daisyUI merges its stock values underneath. The blocks therefore set **every** role (secondary, accent, info, neutral, success, warning, error and their `-content`), or stock oklch colours would leak back in.
4. A `@theme { --color-x }` value would land in `@layer theme` and lose to `@layer base`, so colours never go there. `@theme` carries fonts and the type scale; `@theme inline` aliases runtime variables into utilities (`--color-graphite: var(--mq-text-secondary)` compiles to `.text-graphite { color: var(--mq-text-secondary) }`).
5. Component overrides go in one `@layer utilities { :where(…) {} }` block after the plugin. They beat daisyUI's `daisyui.l1.l2.l3` sub-layers and, being zero-specificity, lose to template utilities — except the five rules (six selectors) that append `:focus-visible` or `:is(:focus, :focus-within)` outside `:where()`: those are (0,1,0), tie with a single-class utility and win by source order, so a template cannot cancel a focus ring with `outline-hidden` (acceptable: the ring is a guide requirement; the one such rule that removes an outline, on `.collapse > summary`, hands the ring to the `.collapse` box instead). A second exception: `.alert` declares `border-width` and `border-color` directly in `@layer utilities` (outside its `daisyui.l1.l2.l3` sub-layer), so at (0,1,0) they beat any `:where()` border declaration; the alert border is steered through `--alert-border-color` (width stays the theme's `--border: 1px`) and the 4 px rail is an inset box-shadow, not a border. `@layer components` is never used (it loses to daisyUI). Unlayered CSS is used for the reduced-motion block and for the app's own classes (`.spinner`, `.page`/`.page--narrow`/`.page--center`, `.app-header`, `.skip-link`, `.htmx-indicator`, `.cal-*`, `.mask-frame`, `.code-block`, `.color-ms`/`.ms-*`, `.ptr--*`), which no daisyUI rule targets; being unlayered they beat template utilities, so a template never tries to override one with a utility.

Each fallback face carries the same `unicode-range` as the web face it stands in for (`"PJS Fallback"`: the latin range of `plus-jakarta-sans-v12-latin.woff2`; `"Inter Fallback"`: the union of Inter's latin and cyrillic ranges); without it the local face covers U+0000–10FFFF, is available synchronously and captures every character the web face lacks, so Cyrillic headings would render in scaled Arial instead of Inter and other scripts in scaled Arial instead of `system-ui`.

**Delivery.** `views/layout.hbs` preloads the two Latin first-paint faces with `<link rel="preload" as="font" type="font/woff2" crossorigin>` (without `crossorigin` the browser fetches each file twice). `workbox-config.js` `globPatterns` gains `woff2` and `svg` so fonts and the mark are precached cache-first and present on the offline page. `src/main.ts` registers a second static root for `/assets/fonts/` with `maxAge: '1y', immutable: true` (precedent for a prefixed static root: `/modules/` at `src/main.ts:73-84`, including `decorateReply: false`; it sets no cache options, so `maxAge`/`immutable` are new here); `bundle.css` keeps `max-age=0` + ETag because its name is not hashed. `@fastify/compress` passes WOFF2 through unchanged, which is why TTF is not shipped.

**Scale.** `@layer base`: `h1, h2, h3 { font-family: var(--font-heading); letter-spacing: var(--tracking-display) }`, h1 32/1.15/700, h2 24/1.25/600, h3 19/1.3/600; body 16/1.55 Inter; `code, kbd, samp, pre` 14/1.5 JetBrains Mono; `table { font-variant-numeric: tabular-nums }`. The utilities `text-display`, `text-h1`, `text-h2`, `text-h3` compile with size, line height, tracking and weight for non-heading elements that need a heading size (verified). Page h1s drop `text-2xl font-bold` and inherit the base style; pages without an h1 get one (calendar: visually hidden; reset/reset-code/update-email/delete-account: the `fieldset-legend` becomes the h1). Wardrobe grid card titles change from `<h2 class="card-title text-sm">` to `<p class="card-title text-base font-semibold">` — a heading per card is noise in the outline (moved forward to PR 3, where the visual baselines showed "Canvas tote" reading as "Canvastote"). Plus Jakarta Sans is never rendered below the h3 size: its word space is 0.17 em against Inter's 0.25–0.28 em, which is fine at 19 px (3.3 px) and runs words together at 14 px (2.4 px). So `.card-title` takes the heading size but not the heading face, a card title that is not a heading renders in Inter, and rule 4 rejects an `h1`–`h3` carrying `text-xs`, `text-sm` or `text-base`. `uppercase tracking-wide` is removed from `wardrobe/index.hbs:124,138,153,168` and `calendar/index.hbs:18`. `text-xs` survives only on the landing footer's legal links (micro, 12 px), each rendered `inline-flex min-h-6 items-center px-1 pointer-coarse:min-h-11` so the target is ≥ 24 px on fine pointers and 44 px on touch screens (ch. 14), the same split as the `-sm` controls in 5.7; `text-[10px]` disappears. Legal and About pages keep `max-w-2xl` (about 75 characters at 16 px) and lose the no-op `prose` class.

## 9. Risks and mitigations

| Risk | Mitigation |
| --- | --- |
| The `:where()` override block is subtle: a later override in `@layer components` or with a class selector either loses to daisyUI or beats template utilities | One-line comment at the top of the block; `brand-css.spec.ts` asserts exactly one `@layer utilities` block and no `@layer components`; this document explains the verified layering |
| `--size-field: 0.275rem` grows every field and button by 4 px and can wrap dense rows at 320 px | Each page PR includes a 320×568 check; `btn-sm`/`input-sm` remain for dense secondary rows |
| The opacity-to-Graphite sweep touches 17 files (15 templates with `text-base-content/NN`, `aiSuggestion.hbs:60` with `opacity-70` on text, and the class string at `calendar.controller.ts:95`, which rule 4 does not scan); a missed `text-base-content/NN` slips through | `brand-css.spec.ts` rule 4 with a shrinking `KNOWN_DEBT`; axe `color-contrast` on seven routes |
| Six-locale PRs (6, 11b) exceed the size convention and carry machine-drafted translations | Values-only diffs reviewed with `git diff --word-diff`; "Needs native review" checklist; parity spec guarantees no missing key |
| Installed PWAs keep the old CSS and icons until the new service worker activates; the offline page may briefly mix old HTML with new CSS | Expected one forced navigation; ship PRs 1–5 in one release; test `offline.html` after `npm run generate:sw` |
| Lighthouse over seven URLs × 3 runs and axe on two projects lengthen precommit | Accept (~10 min); flaky audits are fixed, not relaxed |
| Removing `lazztech_icon.webp` breaks deployments that set `ICON_NAME` explicitly (the watermark route throws) | README row and CHANGELOG entry; `getWatermark()` falls back to `icons/icon-512.png` with a logged warning when the configured file is missing (PR 5, unit-tested) |
| Renaming the photoPicker/files `#loading` ids changes which spinner shows during upload | Retargeted in the same PR; covered by `new-garment-photo.spec.ts` and a manual upload check |
| Moving Sortable init from hyperscript to a script could break reordering | Manual drag test with mouse and touch in PR 9a; `opacity-40` stays literal in the template |
| Dark mode card and surface are the same colour | Per `tokens.json`; Night hairline borders delineate; revisit if the brand adds a second dark surface |
| Fonts fall back to `system-ui` for names outside latin/cyrillic | Documented; adding `latin-ext` later is one file per family |
| Visual baselines drift between machines | Baselines only from the pinned Playwright image or CI; the gate is not in precommit |
| The README's performance figures are pre-throttler and unreproducible | `THROTTLE_LIMIT` for the load test; a new baseline recorded locally in PR 1 (`scripts/results/` is gitignored); the README's `v0.3.1` figures stay as release history (the README body is out of scope, 5.5) and are not cited as the baseline (5.8) |

## Appendix B. Feedback for the brand repository

Found while doing this work; to be reported separately.

1. `tokens/mandatiq-tokens.css` declares `--mq-surface: #eceff5` (raw, line 14) and then `--mq-surface: var(--mq-surface)` (semantic alias, line 32) on the same `:root`; the alias is a self-reference cycle, so the property is invalid at computed-value time in light mode. Cause: `source/mandatiq_brand/css.py` emits raw ids and semantic names under the same `--mq-` prefix and the id `surface` collides with the alias `surface`. `source/tests/test_css.py` does not catch it. Fix by prefixing raw tokens (`--mq-colour-surface`) or the aliases, and add a test that no alias references itself.
2. Every logo and icon SVG uses `<title id="t">`; inlining two on one page duplicates the id. Give each file a distinct id or drop the `aria-labelledby` in favour of `<title>` alone.
3. No font binaries ship with the guide; `fetch_fonts.sh` pulls from an unpinned `google/fonts@main` and emits full-charset TTFs. Consumers need pinned, subset WOFF2 files; consider vendoring the `@fontsource-variable` builds and stating the versions in chapter 09.
4. Chapter 15 notes PWA and maskable icons were removed from the asset set, but products and open-source projects on the design system still need them; a short note on how a product produces its own set (safe zone, opaque tile, sizes) would save every consumer the research.
5. The guide's HTML template applies `font-feature-settings: "cv11"`, which the text never mentions; either state it in chapter 09 or drop it from the template.
